# Contributing to vindOS

Keep vindOS small, native, and free. Work on the current [README milestone](README.md)
and read [AGENTS.md](AGENTS.md) and [ARCHITECTURE.md](ARCHITECTURE.md) first.

For a bug, open a [GitHub issue](https://github.com/peterwangsc/vvindows-connect/issues)
with app/OS versions, GPU, what you did, what happened, and whether it occurred
on hardware or in the simulator. Never attach pairing QR codes, tokens,
credentials, or unreviewed logs. Report security issues privately as described
in [SECURITY.md](SECURITY.md).

Send focused pull requests explaining the user-visible result and how you
checked it. Separate compilation, automated checks, simulator behavior, and
actual Windows/Apple hardware results. Do not start a second capture or
headset session while someone else owns the runtime.

Use the [Apple](apple/README.md) and [Windows](windows/README.md) build instructions.
Keep dependencies and layers to the current concrete need. Keep generated
files, SDK binaries, installers, credentials, and local evidence out of Git.
Only contribute code and assets you have the right to share. Contributions
to vindOS are under the repository's [MIT license](LICENSE); third-party
material must retain its own license and attribution.
